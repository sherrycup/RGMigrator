## 目标与基线

0.5 系列围绕四项目标推进：优先整理脚本结构和提高可读性；事件编辑直接使用 GDScript；恢复原图形标题与菜单；恢复 Message 对话气泡及相关交互。补迁范围以原工程实际实现和已确认范围为准。

现有性能修复已使用 `ver0.5`，保留其历史记录和输出，作为本系列起点；后续沿用 0.40—0.49 的命名习惯，使用 **0.50—0.59** 标识十个小版本。版本标识按字符串管理，不以数值大小推断完成程度。

仅以闪翼为实施、回归和正式导出对象，沿用既有范围：普通魔塔战斗及源已实现的半成品地图功能保留；特殊 BOSS 战、RM 原生回合制战斗及战斗事件、RTP 和读取 RM 旧存档仍按既有排除处理。原公式、源工程只读及直接执行脚本的首错退出行为保持。

本轮已核对的依据：

- 当前模板已有 `templates/runtime` 与 `templates/editor` 的顶层区分，但运行时 `templates/runtime/scripts` 下有 169 个平铺的 GDScript 文件；目录整理需要同时覆盖模板、生成工程、依赖路径与编辑器代码。
- RM 代码镜像的 `Scripts/[group] ...` 按系统、游戏对象、战斗、事件、地图、标题、信息、档案、道具、技能、Orbment、笔记、灵视等职责分组；标题等功能组内同时包含 Scene、Window 及辅助类。
- 当前 `FlashTitleScreen.gd`、`FlashMenuScreen.gd` 仍用 Godot Button 重组界面，不等于原 Sprite/Bitmap 图形表现已恢复。
- Message 已有控制器、布局、气泡绘制、提示和历史等实现，需要核对原入口与实际显示的缺口，在现有实现上修复。
- 事件脚本当前仍是 Ruby 工作源码重新转换，生成 GDScript 只读展示；原生 GDScript 编辑尚未完成。

## 0.50 的目标目录

下列是生成工程的目标职责示意，具体文件归属在 0.50 依据实际依赖确定。迁移器的 `templates/runtime`、`templates/editor` 保持相同职责划分。

```text
生成工程/
├─ runtime/
│  ├─ scripts/
│  │  ├─ 00_Game/             # Game_XXX 对应的状态、对象与规则
│  │  ├─ 01_Battle/           # 普通魔塔战斗、技能效果和显伤
│  │  ├─ 02_Event/            # 解释器、调度、上下文和消息请求
│  │  ├─ 03_Map/              # 人物、事件、地图和楼层
│  │  ├─ 04_UI_Common/        # 通用窗口、光标、文字和绘图
│  │  ├─ 05_Title/            # 标题 Scene、Window、设置和附页
│  │  ├─ 06_Message/          # Message、TextRow、TextBox、HintBox、Memory
│  │  ├─ 07_Archive/          # 档案窗口和展示逻辑
│  │  ├─ 08_Menu/
│  │  │  ├─ Main/
│  │  │  ├─ Item/
│  │  │  ├─ Skill/
│  │  │  ├─ Orbment/
│  │  │  ├─ Note/
│  │  │  ├─ Sight/
│  │  │  └─ MapSystem/
│  │  ├─ 09_Effects/          # 屏幕演出及表现
│  │  └─ 10_Support/          # 缓存、音频、持久化和必要适配，按职责再分组
│  └─ generated/             # 机器生成产物，登记来源与文件归属
├─ scenes/                   # 按对应运行功能分组
├─ addons/rgm_editor/        # 魔塔编辑器；地图、事件、数据库、脚本等再分组
├─ data/                     # 游戏定义与绑定数据
└─ legacy/                   # 原 Ruby 及迁移来源，只读查阅
```

目录数字只控制浏览顺序，不承担代码加载顺序。原脚本最终覆盖、alias 和初始化顺序仍由显式注册和迁移元数据决定。

以镜像中的“标题相关”为例，Scene_Title、Window_Title、Window_Mode、Window_Config 等对应实现集中在 Title 目录。其它功能同样把窗口、场景及专用辅助类放在一起，通用绘制能力放入 UI_Common。装备、商店等子目录按实际入口补充。

Game_XXX 相关实现放在前部，同时建立 RM 类与 Godot 类的对应关系。涉及重命名时同步引用、来源映射、持久化类标识和注册，不为对齐名字建立第二份角色、变量、背包或地图状态。

运行代码依赖运行服务和游戏数据；魔塔编辑器可复用适合编辑器使用的纯数据接口。迁移器、编辑工具和测试代码各有明确归属，正式运行不反向加载编辑器或转译工具。

## 0.51 的可读性要求

- 角色和游戏对象、玩法计算、窗口表现、事件调度、持久化各自有明确责任；页面通过业务接口操作同一份运行状态。
- 展开压缩代码和一行多语句；为重要变量、参数、返回值和信号使用能说明用途的名称与类型；注释说明来源、单位和关键规则。
- 提供原 RM 分组、类、方法到实际 Godot 文件及入口的索引，兼顾按原习惯寻找和按 Godot 职责寻找。
- 常用业务形成可直接阅读、修改的 GDScript 方法；生成器输出也遵循缩进、命名和来源定位规则。必要的 Ruby 语义适配保留明确边界。
- 代码拆分和命名整理与数值规则变更分别处理，保持已确认的原公式、直接执行及首错退出规则。

## 0.52 的原生脚本边界

“用 Godot 代码代替”包括事件列表预览、打开后的编辑内容、保存后的权威源码和实际运行绑定。入口覆盖 355/655 脚本、111 脚本条件、路线 45，以及地图、公共事件、自主路线和强制路线。

日常修改通过具名上下文访问角色、开关、变量、背包、当前地图和当前事件，并明确普通脚本返回值、条件真假、异步等待、路线继续或重试的规则。上下文使用现有运行状态和调度器，不建立独立执行现场。

旧绑定升级时生成可读 GDScript 并保留原来源。未成功迁移的条目明确诊断，不能把 Ruby 文本直接当作 GDScript。用户编辑后的 GDScript 登记作者归属，后续重新迁移或转换不得无声覆盖。

编译诊断定位到用户正在编辑的 Godot 代码，并保留原脚本和地图/事件/页/公共事件/路线来源。草稿、保存、运行发布状态清楚；失败不能显示为修改已生效。复制和移动使用稳定绑定身份，失效回调和等待恢复遵循现有执行规则。

## 图形与 Message 验收原则

0.53 先明确原设计画布、窗口可用区域、字体度量和消息最大文本宽度；据此实现自动换行、裁切和分页，不把 RM 编辑器四行容量直接当作新引擎排版规格。

Message 先检查原入口、控制器、布局及绘制的衔接，再补齐原功能。气泡人物锚点、屏幕边缘位置、箭头、名字头像、选项、提示和历史均核对最终生效的原脚本，沿用现有请求身份和取消保护。与普通事件消息共用业务含义，区分其显示样式。

标题和各菜单按原素材、层次、光标、布局、动画及输入节奏核对。Godot 原生控件可承担输入和布局，但最终外观需要恢复原设计；有按钮、素材已导出或业务可用均不足以单独证明图形还原完成。

图形版本需要真实 GPU 渲染的关键状态截图和实际键盘操作；优先核对原有效代码、原素材和可获得的原画面。无法取得原画面或缺失资源时说明比较依据与限制，不自行补造原功能。
