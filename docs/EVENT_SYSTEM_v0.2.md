## 1. 完整目标和计数口径

ver0.2 系列目标：实现 **RMXP 原生事件功能，排除 Ruby 脚本执行及回合制战斗相关功能**。这里的 RM 按迁移器现有输入格式确定为 RPG Maker XP，不混入 VX/VX Ace/MV/MZ 的新增命令。

RMXP 帮助列出90种主事件命令；排除14项回合制专用及355“脚本”，本计划目标为75种（204含全景/雾，仅战斗背景子类型排除）。另外单独覆盖非战斗续行/分支结束标记、条件与操作数子类型、移动路线子命令、事件页和触发器，不能仅以“命令编号有match分支”宣布完整支持。[RMXP 原版帮助镜像：Events](https://www.rpg-maker.fr/dl/monos/aide/xp/source/rpgxp/event.html)

排除的执行入口为 355/655 Ruby 脚本及续行、111 的脚本条件（type=12）、移动路线的脚本（code=45）。这些入口保留源码与定位诊断；不求值，不替换为假结果。RMXP 原生 122 的操作数是常量、变量、随机、物品、角色、敌人、人物和其他数据，不增加其他 RM 版本的“脚本操作数”。

按用户最新范围，完整目标为地图事件和公共事件；不迁移原生回合制战斗事件、敌人查询、战斗图片域和专用战斗设置。2026-10-08用户再次确认：只排除RM原生Troops回合制功能；工程重载的$game_troop按实际用途分析，数据保留。魔塔式战斗将通过公共事件与自定义结算实现，暂缓，后续单独确定规则；不自动执行或转换 Ruby 公式。

完成标准是：正确参数与目标解析 → 正式状态/服务产生效果 → 按原生规则等待或继续 → 正确刷新与生命周期 → 可验收的结果。Godot 实现可改进性能和维护方式，但不能悄悄改变 RMXP 事件的可见行为。

## 3. 按职责拆分系统

| 模块（拟定） | 职责 | 状态归属和接入边界 |
| --- | --- | --- |
| EventCommandCatalog | 命令/子类型/上下文/参数能力与诊断名称 | 导入扫描和运行时共享；区分接通、部分支持、排除、未实现 |
| EventExecutionContext | 地图、来源事件/页、公共事件栈、指针、分支、循环、等待与执行实例 ID | 每个执行实例独立；来源位置与当前地图上下文分开 |
| EventInterpreter | 执行序列、分支/循环/调用/返回 | 只维护控制流，按分类处理器分派业务 |
| EventScheduler | 主事件、待启动请求、地图并行、公共事件自动/并行、预算与生命周期 | 地图拥有调度器；并行采用协作调度，无需系统线程 |
| EventWait | 时间、界面、路线、转场等等待/取消协议 | 使用状态或完成信号；带执行实例身份，旧回调不能恢复新事件 |
| EventPageController | 页条件依赖、最高有效页、触发锁、暂时删除、并行实例启停 | 与 MapEvent/MapRuntime 协作，不复制地图人物状态 |
| EventUIBroker | 对话、选项、数值、商店等界面请求的单一占用与排队 | 请求回到原解释器；并行对话不覆盖主事件对话 |
| 分类命令处理器 | 消息/状态与查询/人物地图/屏幕/音频系统/角色/场景 | 调用 RuntimeState 与现有服务，不再复制角色、天气、背包等真值 |

0.21 已拆执行核心、调度、等待与界面请求入口；现有业务命令保持兼容，分类处理器随着后续命令接入逐步迁出。Game 保留组装职责，MapRuntime 保留地图/通行/目标解析，MapEvent 保留人物实体职责。

## 5. 主命令之外的必要功能

### 5.1 事件页、触发和公共事件

- 地图页条件：两个开关、变量阈值、独立开关；多个成立时采用最高页号，无有效页时不显示、不阻挡、不触发。XP 原生页不增加后续版本的角色/物品页条件。
- 页属性：人物/图块图形、色相、方向、图案、透明度、混合，移动类型/速度/频度，自定义路线，行走动画、踏步动画、方向固定、穿透、置顶显示。
- 地图触发：确认键、玩家接触、事件接触、自动执行、并行处理；脚下/前方/柜台、朝向锁与结束恢复、接触失败尝试、移动/跳跃期间门禁均须覆盖。
- 自动事件在条件持续成立时继续执行；通过切换开关/独立开关退出。并行事件有自己的执行实例，列表结束后按原生更新规则再次执行。
- 公共事件：无触发时供 117 调用；开关控制的自动/并行实例；开关关闭、重新开启、递归/嵌套、被物品/技能预约触发时的完整生命周期。
- 116 删除当前地图实例中的事件，刷新不会复活；重新进入地图恢复。删除显示/碰撞/并行实例与执行列表剩余命令的边界按 XP 原生规则验证，不能直接把删除节点等同于中断 115。
- 换图保留应继续的主事件命令，取消旧地图并行/目标引用；“本事件”不能误指新地图同 ID 人物。源地图/事件/页仍用于诊断。

### 5.2 条件与变量查询

111 的非脚本条件完整覆盖：开关、变量六种比较、独立开关、计时器、角色是否在队伍/名字/特技/武器/防具/状态、人物方向、金币、持有物品/武器/防具、RM 按键按住状态。敌人条件排除；其余在 0.22。

122 完整覆盖赋值/加减乘除余、单个/范围、常量/变量/闭区间随机，以及以下查询：

- 物品数量。
- 角色等级、EXP、HP/SP、MaxHP/MaxSP、力量/灵巧/速度/魔力、攻击力/物防/魔防、回避修正。
- 敌人操作数属于回合制战斗，排除。

## 8. 适合 Godot 的改进与兼容边界

- **协作调度替代忙循环**：共享帧预算并保存指针，重负载跨帧继续；固定调度顺序确保结果可复现。预算耗尽本身不当作事件错误，异常持续占用另做定位诊断。
- **按依赖刷新事件页**：开关/变量改变只标记有关事件页为脏，在安全边界批量刷新，避免每帧扫全地图；不能把应立即生效的页切换延迟到整段事件结束。
- **等待状态统一**：时间、UI、路线、转场均使用完成条件和身份令牌，避免忙等、重复启动或过期回调恢复错误实例。
- **命令能力统一**：共享描述与参数验证，使预检和实际运行一致；保留“命令支持但某子类型未支持”的精确诊断，不用一个 supported=true 掩盖缺口。
- **控制流预索引**：可预编译标签与分支/循环边界，减少反复线性查找；原命令位置映射保留，不能改变嵌套跳转和执行顺序。
- **兼容与增强分开**：寻路、额外消息标签、阻挡自动跳过、自动事件只执行一次等可以成为未来可选增强；原生迁移默认维持 XP 行为，尤其不把“接近玩家”擅自改成寻路。

**单位必须逐命令适配，Godot 不照搬“乘 2”。** 用户已明确：新引擎能保证正确时间就无需乘二。旧实现中 106 及若干色调/图片时长先乘 2 再由 40 FPS 推进，是旧命令单位与更新帧计数之间的换算；新实现直接把原参数转换成秒。例如等待参数 20 → `20 / 20.0 = 1.0` 秒，再按 delta 推进，不额外乘二、不增加时长、不依赖 Godot 帧率。天气时长没有相同乘二，音频淡出参数又是秒，不能沿用一个通用除数。后续接入前以原生标准脚本与独立夹具复核各命令的实际时长，底层只接受秒且不重复换算；233 旋转和 225 震动还需要原生速度/强度转换。帧预算可以跨帧，但不以增加无条件等待来改变正常剧情节奏。
