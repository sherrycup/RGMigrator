# 0.48 移动、事件及菜单性能反馈修复

2026-10-14。用户反馈所有地图在按方向键时掉到个位数帧率，静止正常，ESC打开/关闭菜单明显卡顿。本轮仍为0.48反馈修复，未将0.49整体验收提前记为完成。

## 定位和修复

- 普通步行到达每个格子都创建完整脚本事务，重新解析只读战斗规则并配置模拟器；角色临时副本和快照校验又重复配置相同规则。复用只读规则，保留各事务独立的模拟器、角色及可变数据；无中毒且未持有对应能力物品时，原五个步行处理入口均无操作，直接返回。中毒、隐形、领域、夹击和钩子仍走完整事务和失败回滚。
- HUD收到步数和时钟通知后重画同样的背景、数值条及边框。数值/角色布局未改变时复用现有纹理；物品栏变化仍请求绘制，HP等实际变化仍更新。菜单方向键只更新选中样式，不重新创建全部控件。
- 对象图复制、检查和编码此前逐个扫描所有已访问容器，形成平方级重复工作。按不递归的结构摘要分桶，最终仍以is_same判断身份；保留相等但不同的容器、跨字段别名及循环。数据可保存性检查直接遍历，不再生成完整编码临时树。方法源码SHA按文件去重，完整来源校验保留。
- 事件前自动记录此前同步序列化、临时文件校验及原子替换，GPU实测约1.26秒。主线程仍在事件前捕获并完整校验脱离现场的快照；单个后台写入线程只序列化/写入已校验的普通数据，不访问游戏节点。按顺序写入；待写入或写入失败的快照可在当前会话撤回，失败会报告。显式存档、新游戏和退出排空写入队列，同帧重复记录直接跳过，不等待后台任务。快照捕获/校验仍有一次性耗时，不宣称所有事件都已达到16.7毫秒。
- 额外发现原0103的check_event(x,y,reg=nil)缺少适配，会在Map010事件72等原条件中生成诊断并占用输入。补齐当前事件坐标、死亡标记、字符串/RegExp名称匹配，返回事件ID或nil；不执行Ruby。

## 性能证据

在Godot 4.7.2标准版、Compatibility、GTX 1660 Ti上，使用原Map010和实际Game/PlayerController/HUD/MenuCoordinator。方向键通过Godot Input动作按住，菜单通过实际ESC/方向键事件分发；另测事件前记录及重复菜单开闭。探针在私有副本中临时加入分段计时，不改变正式模板。启动素材和角色初始化的冷帧单独记录，不能混同稳定地图帧率。

初次GPU样本：移动平均45.568毫秒，P95为156.136毫秒；事件前记录1257.786毫秒。初步修复GPU样本：移动平均17.145毫秒，P95为16.915毫秒，单次最高69.628毫秒；事件入口165.847毫秒；首次菜单打开43.633毫秒，后续三次约12毫秒，关闭0.322毫秒。最终修复及正式输出的结果见tests/VERIFICATION_v0.48.md追加记录。机器和现场状态影响耗时，不能把这些样本换算为全部地图、全部事件的保证。

最终正式副本不插桩，离屏测试前后均禁用VSync以排除窗口交换等待。旧版移动平均48.331毫秒/P95 120.029毫秒，事件1257.877毫秒；修复版移动平均17.089毫秒/P95 16.948毫秒，事件116.873毫秒，菜单再次打开约10—12毫秒、关闭0.327毫秒。正式工程保留原VSync设置。全套结果和实际画面随修复工程的tests/VERIFICATION_v0.48_PERFORMANCE.json、performance-map.png、performance-menu.png附带。
