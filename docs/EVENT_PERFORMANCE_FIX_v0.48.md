# 0.48 战斗与拾取事件卡顿修复

2026-10-14—15，针对闪翼普通战斗、血瓶、宝石和物品事件的停顿。修复工程使用新的 `../output/0.48/fix-event-hotpath/黎之闪翼（开发中）_Godot` 目录，由原 RM 工程重新运行正式迁移流程。包含此前脚本工作区、移动/菜单和音频修复，历史输出保留。

## 原因和实现

此前测试的单条开关指令没有覆盖真实事件中的公共事件调用链。原 Map010 的一次拾取会执行约 15–24 个脚本事务；多个事务、首次脚本编译、完整事件前记录检查都集中在一次更新中，造成数百毫秒的阻塞。

- `ScriptSemantics.program` 持有已编译 GDScript 的强引用，避免临时 `load()` 引用释放后重复编译。每次入口仍核对文件 SHA256，同一帧内修改生成代码也会重新读源并编译。`ScriptRuntime` 按符号索引筛选定义，保留源加载顺序、重开、alias、错误和来源校验。
- `ScriptQueryProof` 只分析副作用，不执行 AST。名称正则、临时标量比较和两扇门每帧的坐标查询，在生成文件 SHA256 仍与工作区归属一致时，直接执行原生成 GDScript 的只读路径。未命中的单一分支不复制整份状态；进入分支正文前立即退出预检查，再用完整事务重跑。任何实际赋值、对象比较、定义加载或手工改过的生成代码均回退完整事务。捕获组、事件字段的共享/循环关系以及失败回滚仍保留，临时数据清空和全局调试入口不视为只读。
- `check_event` 保留地图定义的遍历顺序，用一次临时索引访问人物，避免在外层循环内再逐个扫描人物数组；先比较坐标，再读取死亡标记和名称。
- 进入游戏地图时预加载生成程序及动画数据库；首次加载时间会增加。动画只缓存未经修改的只读源定义，测试定义和现场覆盖仍重新校验；播放游标和材质继续归动画实例。
- `EventScheduler` 给主解释器和并行解释器共享每帧约 4ms 的执行预算，在完整事件指令之间让出帧。预算的首个执行机会逐帧轮换，避免慢前台指令让并行事件一直得不到执行。各解释器的等待每次调度仍只推进一次。单个 GDScript 片段保持事务提交和失败回滚，不能任意中断其内部执行，因此该预算不是单帧耗时的硬上限。
- 自动记录先在主线程捕获事件前的脱离现场快照，再分帧完成同一套存档验证。期间暂停地图推进并阻止新事件、菜单和显式保存；音频继续。验证成功后预留编号并执行原事件，后台只顺序写入已脱离现场的数据。取消、重置或换图时不得发布过期记录。
- `SaveGraph` 保留 `is_same` 身份判定、共享/循环关系和原深度/节点/元素限制；批量浅复制后只递归容器，减少标量遍历开销。新建的原生人物快照可直接复用，休眠现场和可变脚本数据仍完整脱离原状态。
- `SavePreparation.gd` 从 `SaveCodec.prepare` 自动生成分帧检查版本。修改同步校验后，必须运行 `D:\Python\python.exe tools/sync_save_preparation.py`，再以 `--check` 检查一致性；生成游戏不依赖 Python。
- 复制角色当前状态时复用只读规则与经验表，保留完整恢复校验，避免重新执行新角色初始化。HUD 数值变化只重画条形图，复用背景、技能框和未变化的角色图像。
