## 0.36已确认的扩展范围

- 沿用数据库定义图块集、地图引用图块集的结构，地图面板明确显示图块集名称，并提供编辑当前图块集的入口。数据库在每格直接显示通行、方向和优先级等标记，支持逐格及连续修改。
- 普通图块集可以引用多张素材图片，在图块面板和属性编辑区按素材顺序纵向排列。用户准备相同宽度及符合现有图块规格的素材；不缩放、不补边、不自动对齐。组合共享原图片，不生成额外合成大图；配置与属性表仍有少量数据开销。自动图块继续独立配置。
- 素材尾部追加保留已有图块编号；换序、移除或尺寸变化必须保护地图及图块事件的编号对应关系，不能让已有地图错图。属性编辑、地图绘制、图块事件图形和正式运行共用素材映射。
- 地图默认保留三层，按需追加图块层。图层按钮、绘制/预览、复制粘贴、新建与尺寸调整按地图实际层数工作；事件编辑模式独立，不继续用固定索引3表示事件。旧RM地图保持原有三层和图块数据。
- 通行与人物遮挡需核对新增图层后的行为，增加图层不等于增加图块优先级。独立装饰层的通行/遮挡规则需明确设计，不能仅凭图层名称自动改变旧规则。

当前交付为ver0.39；操作见docs/EDITOR_v0.39.md，验证见tests/VERIFICATION_v0.39.md。历史ver0.37数据库操作见docs/EDITOR_v0.37.md，验证见tests/VERIFICATION_v0.37.md。ver0.36已实现上述扩展；操作见docs/EDITOR_v0.36.md，验证见tests/VERIFICATION_v0.36.md。事件行走图双击与下方按钮入口按用户意见暂保留0.35交互，后续再统一考虑；0.38反馈交互与0.39完整指令配色已合并完成。

### 编号容量方案与性能评估

- 推荐采用最大编号与可留空的固定编号槽位，适合100段放血瓶、200段放宝石等区域规划；区间中间不需要填满，清空条目也不应重新排列ID。已有空白默认定义和未知字段保持原样，不为统一占位形式批量改写原数据。
- 新增物品等数据库空槽位可用轻量空值保存，首次实际编辑才建立默认定义；开关/变量名称使用空字符串保留编号。缩小最大编号前检查尾部已有内容、关联引用及测试保留编号，拒绝截断有效数据；相关属性表和引用选择器按新增实际定义正确处理。
- 现有RuntimeData缓存解析后的数据库并直接按ID索引读取，扩展容量不会要求每次查询扫描全部空槽位。按空值JSON估算，200扩至500新增300个槽位约增加1.5KB紧凑文本，制表符缩进约2.1KB；这些仅是序列化体积估算，并非引擎内存或运行耗时测量。
- 主要性能关注点在编辑器：EditorDatabaseDialog当前会重建整份条目列表，EditorDocuments撤销历史会深复制整份数据。0.38实现容量管理时应结合分页/按编号区间显示，避免逐个槽位执行扩容事务和重复列表刷新；按一次扩容一次历史项处理。开关/变量已有每组100条的显示基础，可以复用。
- 本版实施时检查500及5000编号规模下的扩容、跳转、切换、搜索、撤销、保存重开，分别记录交互与保存耗时。已实现500/5000编号专项与真实界面检查；具体耗时、范围和验收证据见tests/VERIFICATION_v0.39.md。新增图块可见区域裁剪、滚动重绘和主题更新去重，避免大图块集与长事件列表重复处理不可见内容。
