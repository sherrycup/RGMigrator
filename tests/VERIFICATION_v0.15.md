## 标准商店

独立标准夹具检查 RMXP 两参数商品格式、JSON 浮点整数 ID、重复商品、坏引用、非 XP 自定义价格参数、奇数半价取整、零价购买/拒绝出售、余额/99 件库存/金币上限、无效数量、身上装备不自动出售及过期报价重新校验。取消或失败不部分修改金币和背包，数据库定义不变。

真实 Game / MenuScene 键盘检查购买→数量→取消→确认、出售、返回原地图；验证地图实例、位置、朝向、开关变量保持。仅游戏时间等无关通知不重建商店；库存外部改变导致待出售商品消失时，取消该确认而不是误卖下一行。

真实事件解释器执行 302 + 605，等待期间禁止地图菜单/存档；关闭商店后执行下一条开关命令并恢复玩家。无效商品中断事件；坏续行诊断精确指向原事件、页和第 2 条 605，孤立 605 同样诊断。没有扩展状态指令 313 或状态条件分支。

## State 登记接口

覆盖附加、解除、清空、存在判断、排序独立 ID 数组、重复操作、坏引用、离队角色及重新加入初始化。普通状态与装备自动状态来源分离：解除/清空普通来源不误删装备来源，卸装不误删单独附加来源。新游戏测试模式给 2000 金币和一个中性初始状态；关闭测试模式不发放、不显示工具。

标准夹具使用 `zero_hp=true`、`slip_damage=true` 和 `plus_state_set` 验证这些字段不自动触发死亡、伤害或连带状态，HP/SP 不受这些标志改变。已有属性倍率显示及上限截断沿用，测试状态倍率均为 100；不把样例状态 ID 1 硬编码为死亡。

测试配置采用 schema 3，新增两个不覆盖原 ID 的完整 28 字段 States 定义及商品 price；生成器检查原数据库不变。买卖后附加状态、保存、重开新游戏再读档，交易金额、库存、普通状态 ID 正确恢复且不重新发测试物资。装备状态由恢复的装备重算。新测试定义变化导致旧测试存档不兼容时明确拒绝，原文件不自动修改。

## 768×768 性能

测试预热所有菜单后交替 Map585 与物品、装备比较、技能预览、存档槽、原动画双位置、商店、状态工具。关闭垂直同步，实际 OpenGL 渲染；自建的其他 Godot 测试已结束。用户原有 output 编辑器及其运行游戏仍保持打开，没有为测试擅自结束用户进程。

60 FPS 上限，60.002932 秒 / 3594 帧：平均 **59.897 FPS**，P95 **18.001 ms**，达到平均 ≥59 / P95 ≤20 ms 的目标。节点 **101→101**、资源 **61→61**、显存 **40,815,110→40,815,110** 字节；静态内存 **116,569,617→116,657,981** 字节。本次短测无节点/资源数量累积，不保证所有工程或长期绝无泄漏。原始记录为 `v015-final-sample2/menu-benchmark.json`。

补充不限帧、预热后 30.00115 秒 / 10073 帧：平均 **335.754 FPS**，帧间隔 P95 **5.516 ms**、P99 **6.708 ms**，最长 **83.356 ms**；超过 16.667 ms 的比例 **0.07942%（8 帧）**。因此不能宣称逐帧稳定 60 或完全没有卡顿；本轮未记录这些长间隔的完整主线程调用栈，不据此归因于某个模块。

引擎渲染计时开启，渲染 CPU（帧准备加主视口渲染）P95 **3.107 ms**、主视口 GPU P95 **2.297 ms**，GPU 计时可用。这些是渲染部分而不是完整脚本/引擎帧成本，且不能相加当作总帧时长。证据 `v015-final-sample2/menu-uncapped.json`。限帧 P95 包含等待与系统调度，不能当作纯绘制耗时。

## 边界

- 本版是 Godot 标准功能替代，没有自动执行/转换 Ruby，不恢复魔塔自定义商店、额外货币或战斗。
- State 仅登记/查询及已有显示：不新增死亡、中毒、限制、抗性概率、连锁、回合/受击解除、战斗持续时间或状态循环动画；物品状态效果仍不执行，技能仍不施放。
- 不新增 RTP、旧 RM 存档、地图编辑器或事件编辑器。测试入口是为了无需反复编辑原 RM 工程，不是正式游戏的新菜单命令。
- 实际自动渲染使用 Dummy 音频，音效听感和操作手感仍需用户按验收清单确认；ver0.14 已获用户验收，不等于 ver0.15 已获人工验收。
