# RGMigrator ver0.15 人工验收清单

本版范围：标准商店，以及 State 的附加/解除/清空/查询接口；不是完整状态效果引擎。不新增战斗、技能施放、自定义 Ruby 商店、旧 RM 存档读取。

## 准备

1. 重新迁移到新的空目录，勾选“准备测试物资”，用 Godot 打开并运行新输出。
2. 点击新游戏：原测试药品、装备、特技仍在；额外准备 2000 金币与一个中性初始状态。
3. 原初始化事件若有不兼容诊断，先按“关闭”；Esc/X 打开菜单。主菜单顺序不变，底部新增“测试商店”“状态接口”两个测试按钮，鼠标点击进入。
4. 测试入口无需回 RM 添加事件；本版不改出生地图、不跳过源事件。旧导出不会自动升级。

## 商店

- [ ] 进入测试商店，有购买/出售/离开，显示金币；选择购买能看到测试药品、武器和四类防具、价格、说明、持有数量。
- [ ] 选择一瓶血瓶：数量窗口默认 1，←/→ ±1，↑/↓ ±10，可用鼠标数量/最大按钮。确认前金币和库存不变；Esc 取消也不变。
- [ ] 买 2 瓶血瓶：每瓶 100，金币减少 200、血瓶数量增加 2。退出商店→物品页，数量同步；没有自动使用药品。
- [ ] 出售刚才买的一瓶血瓶：金币增加 50、数量减少 1。出售不自动卸下或卖掉身上装备。
- [ ] 武器/防具显示职业能否装备及标准属性对比；‹/› 可切换队员。买武器后角色实际装备未改变，需去装备页更换。固定槽位有提示。
- [ ] 金币不足/该物品达到 99 件时不能再买，失败有明确原因，不扣钱、不加库存。可重复买血瓶降低余额后检查；不要求改源数据库。
- [ ] 逐级返回购买/出售列表→命令→原菜单→地图，不重载地图、不丢位置/朝向和其他状态。
- [ ] 原工程可到达的标准 302 商店事件可正常打开；关闭商店后继续下一条事件。没有可达商店时，测试入口足以验收 UI，自动测试另覆盖 302/605。

## State 接口

- [ ] 点“状态接口”，选择队员与“测试用·可增删状态”。先查询得到“否”，点击附加再查询得到“是”，ID 列表更新。
- [ ] 再次附加不出现重复 ID；解除后查询“否”，再次解除不报错或重复修改。
- [ ] 清空普通状态后普通 ID 列表为空；有效 ID 列表可能保留原装备提供的状态，这不是清空失败。
- [ ] 返回主菜单/角色详情，状态名称同步；接口操作不把角色重新初始化。
- [ ] 本版不根据 State 自动触发中毒、死亡、连锁、概率解除或循环动画。两个测试状态无倍率变化；原状态的已有倍率显示保留，不以自定义 Ruby 效果为验收条件。

原装备状态的来源一致性、离队角色与无效引用已由标准夹具验证，不要求为人工验收回 RM 新建状态/装备。底层直接操作接口见 README；这些是 GDScript 接口，不是 Ruby 兼容 API。

## 存档及回归

- [ ] 买卖后附加测试状态，保存槽位，真正退出再继续游戏：金币、库存及附加状态保持，不再次发 2000 金币或恢复已清空的初始状态。
- [ ] 返回标题→新游戏：金币回到 2000，库存按配置重置，初始状态重新提供，可增删状态尚未附加。
- [ ] 将导出 `data/test_setup.json` 的 enabled 改 false 后重新新游戏：没有测试金币/状态/入口；原标准商店事件仍可使用。
- [ ] 血瓶恢复、装备更换、特技学习/遗忘、并发动画、四槽位存读档和地图移动保持正常。
- [ ] 640×480 等实际尺寸下中文、商品、属性、数量框、测试按钮和状态列表可读，错误原因可查看。

只调整 initial_gold/shop_goods/initial_states 等配置后重新新游戏即可，不需重新迁移。更改 States/价格等定义会影响旧测试存档的兼容性；不删除正式存档。验证记录见 [VERIFICATION_v0.15.md](VERIFICATION_v0.15.md)。
