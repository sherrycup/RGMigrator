# ver0.21＋ver0.22 联合人工验收

在Godot 4.5+标准版打开本次生成工程的project.godot。保持data/test_setup.json的enabled=true，从标题“新游戏”进入。源工程含Ruby/待接入命令时，先关闭诊断；不要把诊断当作验收流程的消息。地图空闲后：**Esc → F6 → 正式事件验收地图**。

## 1. 等待、公共事件、循环、变量与消息一起验收

1. 进入地图后等1秒。“自动”变为1，自动事件切换第二页，玩家恢复操作。
2. 点击**联合流程**。文本与两项选择同窗显示，选择“运行3次”。
3. 每轮公共事件等待0.5秒，随后绿色消息显示第1/3、2/3、3/3轮，累计依次为1、3、6。点击“继续”进入下一轮。HUD同时显示循环次数与累计变量；对话期间地图/公共并行计数继续增长。
4. 第3轮后条件分支跳出循环，最终消息显示共3轮、累计6及计时器剩余秒数。关掉消息后玩家恢复操作。
5. 再运行“联合流程”，选择**自行输入**，输入2，确认后结果应为2轮、累计3。数字窗口读取之前的变量作为初始值，最多2位，可直接键入或使用微调按钮。
6. 输入0或大于5的值，会出现条件消息，并改为3轮。选择最初窗口的“取消”或按Esc/X，进入取消分支，显示取消消息后结束；不会开始循环。

## 2. 消息位置、窗口、控制字符、按键与分页

1. 点击**文本与按键**。顶部透明消息使用绿色文字，显示当前角色名；金币窗口出现在右下。提示栏暂时隐藏，避免文字重叠。
2. 点击继续，出现中部普通窗口等待新按键。按住上一条消息的确认键不会自动填值；松开后重新按键。
3. 方向下/左/右/上写入2/4/6/8；Shift=11，Esc/X=12，Enter/Space/Z=13，A/S/D=14/15/16，Q/PageUp=17，W/PageDown=18。后续消息与HUD应显示编号。
4. 继续后出现底部普通消息，第2行读取按键变量，第3行显示反斜杠与普通方括号。超过四行会分页；第一页确认只翻页，最后一页确认才结束事件。长行也会按窗口宽度分页。
5. 消息中的变量在该消息打开时取值；并行计数在HUD继续增长，下条消息重新读取变量。只有RMXP的V/N/C/G及双反斜杠是控制字符，不执行Ruby或富文本代码。

## 3. 保留0.21触发与现场验收

1. 方向键移动到柜台下方，朝上按Z确认人物。关掉首条消息，公共事件等待1秒；返回消息显示实际确认次数和后台变量。
2. 左下(2,7)触碰点显示消息。关闭后执行暂时删除116，下次更新继续变量增加；再踩不会触发，页刷新也不会复活。
3. 点击“启停公共并行”，仅公共并行计数启停，两条地图并行保持运行。菜单/商店暂停地图及事件等待；单纯前台等待或对话锁住玩家，后台并行继续。
4. 在所有消息结束后按F7或点击“退出”。原地图、角色位置、变量、消息选项、计时器及原并行执行现场恢复；验收地图变化不写入正式存档。
5. 保持640×480、800×480、768×768检查消息、输入、HUD与按钮可见。脚本、原生回合制战斗不在迁移范围；自主移动/强制路线在0.23实现。

## 4. 其他0.22规则

EventValueTests自动验证全部非战斗条件/变量操作数、负数除法与余数、±99999999变量上限、范围共用随机值、金币/库存上限、非法参数原子拒绝和存档兼容。存档成功才增加次数，失败不增加；消息位置/窗口随进度恢复，旧schema1缺字段补默认。执行中的事件栈、并行及本图暂时删除状态仍未持久化，相关存档入口会给出原因。

验证记录见[VERIFICATION_v0.22.md](VERIFICATION_v0.22.md)。
