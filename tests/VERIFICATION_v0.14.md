## 同一目标连续动画与自然结束

地图测试先推进玩家动画，再对同一个事件 7 连续执行两条非阻塞 207（动画 ID 1、2）。验证三个实例共存：两个事件动画保留不同 ID，第一个已推进至帧 1，第二个仍为帧 0；取消最新实例不取消前两个。动画不改变 HP/SP，也不执行技能效果。

新增回归覆盖自然播放结束、节点真正释放后再次执行 207；测试界面也覆盖同目标不同 ID、自然结束后计数归零和再次播放。它不是单一 `animation_id` 被覆盖的模型：每次播放创建独立节点，分别持有帧数据、时间与清理状态。

首轮长时间渲染发现已释放节点传入带 `Node` 类型的 `Array.filter` 回调时转换失败，随后触发数组类型错误。该轮虽然 FPS 数值达到目标，整体仍判为失败；证据保留在 `v014-first-benchmark-render.log` 和 `v014-first-benchmark.json`。改为先检查原数组元素有效性、反向移除失效项，修复地图及动画测试页两处；增加上述回归后，最终长测无 ERROR / SCRIPT ERROR，才判定通过。

## 交付边界

- 标准 Godot 功能替代，不自动转换 Ruby、自定义菜单、额外货币/属性、魔塔公式或自定义数据对象；不读取 RM 旧存档。
- 仅保存当前已有持久运行状态，不保存运行中的事件/动画、瞬时音效和当前 BGM/BGS 播放进度；没有新增事件指令，352 唤出存档仍诊断。
- 新存档有格式、项目、数据兼容性与完整性检查，不是加密、防作弊或绝对断电安全保证。修改数据库/地图/system 或测试定义后可能不能继续旧进度。
- 存档不持有场景节点；读档重建地图并依据保存的开关变量选择事件页。菜单关闭依然复用原地图。当前运行时还没有完整自动/并行事件调度。
